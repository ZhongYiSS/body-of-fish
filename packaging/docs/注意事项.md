## 三、架构一句话

- **宿主 plugin**（`src/host`）：注册 `/dsh-pet-7340/*` 路由与「桌面管道」两个入口，都进 `handlePetRoute` 纯函数；另有 `apply(ctx)` 做生命周期、菜单、桥插件安装、状态轮询。
- **客户端**（`src/client`）：轮询 `/state`，按 `say/anim` 渲染气泡与动作；菜单点击回 `/menu/click`。
- **独立模式**（`src/standalone`）：自己起 HTTP 服务（默认 3080，带 token 安全层），把宿主逻辑跑在一个 Electron 壳里，不依赖 DSH。
- **Electron 壳**（`runtime/electron-helper`）：真正开窗口、画精灵、托盘、菜单渲染（`sprite.js`）、菜单树拼装（`shared-core.js`）。
- **桥插件**（`packaging/bridge-plugin`）：DSH 里的第三方插件，负责「身体 ↔ DSH 会话」三条链路（见第六章）。

硬契约：浏览器/桌面/独立三端行为一致；改行为优先改 `src/host`，少碰壳。

## 四、五个最常见的改法（recipes）

### 4.1 加一条 HTTP 路由

1. 在 `src/host/index.ts` 的 `handlePetRoute` 里找 `const rest = ...` 之后的分支（`if (rest === 'config')` 一带，约 2770 行起），加一个 `if (rest === 'xxx')`。
2. 返回 `{ kind: 'json', obj }` 或 `{ kind: 'text', ... }`，方法不符显式 405。
3. 若客户端要调用：`src/client/*` 里用现成的 request 帮助函数，路径 `/dsh-pet-7340/xxx?surface=...`。
4. 有对外契约的（第三方会用）再补 `scripts/check-openapi.mjs` 的文档。

### 4.2 加一个右键菜单项

1. 文案在 `src/host/pet-menu.ts`（327 行）：加 label 常量 + 菜单树里挂一项 + `parseMenuId()` 认这个 id。
2. 点击处理在 `src/host/index.ts` 的 `rest === 'menu/item'` / `menu/click` 分支。
3. **壳的硬约束**（`runtime/electron-helper/shared-core.js` 的 `buildPetMenuTree`）：
   - 只按**全角冒号 `：`** 切层级，最多两级；
   - 同一 owner 下项数有上限：宿主 `src/host/menu.ts:33` 是 `ITEMS_MAX=40`，`src/host/pet-menu.ts:19` 的注释还写着 20（旧值，以实际注册的宿主白名单为准），别堆到上限；
   - 标签别太长（建议 ≤32 字），带 ✓ 表示开启态。
4. 想让它「始终可见」：别放进 `状态 ▸` 的子项里做条件渲染，直接挂根菜单（例如「装插件到 DSH…」）。

### 4.3 加一个设置项

1. 表单在 `src/standalone/pet-settings-page.ts`（276 行），分六组：外观 / 手感 / 人格 / 对话模型 / 看图 / 声音。
2. 类型与默认值在 `src/shared/config.ts`；合并与写盘在 `src/host/config.ts`。
3. **白名单**：`PUT /config` 是「白名单重建」写盘——不在白名单里的字段会被整份抹掉。加字段必须同时加进对应白名单（顶层字段见 `config.ts` 顶部注释；实例级固定白名单是 id/name/size/4 个开关/display/position + `whisperPrompt`）。
4. 高级字段（例如顶层 `whisperPrompt`）设置页不展示时，直接让用户改 `main-config.jsonc` 再点「重载配置」；`POST /config` 是「用内置默认原文覆盖用户层」，慎用。

### 4.4 加一个桥端点 / 改注入行为

见第六章。核心：`packaging/bridge-plugin/lib/index.js`（793 行），`API_PREFIX='/api/pet-bridge'`，端点用 `webServer` 注册；注入消息必须带 `role` + 唯一 `id`（血泪教训，见 7.1）。

### 4.5 加一个动作/动画

- 动作池与解析：`src/host/pose.ts` / `src/shared/motion.ts`；菜单「动作 ▸」在 `pet-menu.ts`。
- 播放回执：`/anim` 返回 `playbackId`，`/playback` 查真实结果——别用「发了请求」当成功。

## 五、桥插件（最容易被改坏的地方）

### 5.1 它是什么

`packaging/bridge-plugin/` 是一个独立 npm 包（`package.json` 名称 **`body-of-fish-bridge`**），被 electron-builder 以 `extraResources` 塞进安装包 `resources/bridge-plugin`；身体菜单「装插件到 DSH…」把它复制到 `~/.dsh/plugins/body-of-fish-bridge`，并写 DSH profile。

三条链路：
1. 身体 → DSH：`POST /api/pet-bridge/say` → `agent.followup()` 投进选中会话；
2. DSH → 身体：`agent/turn-stopping` 取最后一条 `assistant/message` → 身体 `/summarize` → `/broadcast`（+`/say-loud` 朗读）；
3. 图片 → 身体：`agent/inbox/inserted`/`session/event` 看到 image block → 读附件文件 → 身体 `/look` → 描述 followup 回会话。

### 5.2 装进 DSH 的三个硬条件（缺一个就「插件页显示未安装」）

1. **文件**：`~/.dsh/plugins/body-of-fish-bridge/` 下必须有 `package.json`、`lib/index.js`、`cordis.patch.yml`；
2. **`cordis.patch.yml` 里的 `name` 必须等于包名** `body-of-fish-bridge`（写旧名 `dsh-pet-bridge` 会在加载时对不上）；
3. **profile 里除了 `dependencies` 的 `link:` 和 `dsh.profile.bundles`，还要有 `~/.dsh/profiles/desktop/node_modules/body-of-fish-bridge` 的链接（junction）**。DSH 解析 bundle 走 Node 解析，解析不到会**静默 skipped**（只写 stderr），插件页就显示未安装。

> 0.4.1 已修：`installBridgeToDsh`（`src/host/index.ts:460` 起）拷完插件后会**幂等补建**这个链接（已存在且指向对就跳过，指向错先删再建，真实目录挡路则报冲突不删），失败写进返回文案，不再静默。旧版 0.4.0 仍需手动补链接。

### 5.3 兼容旧名（别乱改）

- `SOURCE_KIND = 'plugin:dsh-pet-bridge'`：会话消息的来源标识，**改了历史消息对不上**，保持旧值；
- 老运行时文件 `~/.dsh/dsh-pet/standalone-runtime.json` 兜底读取；发现文件先读新名 `body-of-fish-bridge.json` 再读旧名 `dsh-bridge.json`（`src/host/dsh-bridge.ts:19/22/100`）；
- 请求头 `x-dsh-pet-token`、路由 `/dsh-pet-7340`、协议 `dsh-pet-bridge://` 都保留。

### 5.4 端口漂移

DSH 重启后端口会变（实测 49265→54022→49230）。桥插件每 20 秒重写发现文件（写到身体数据目录，即 `petRuntimeFile` 同目录，见 `publishDiscovery`），桥插件每次请求前重读 `standalone-runtime.json`；别把端口写死。

## 六、已知的坑（改之前先读）

1. **注入消息必须带 `role` + 唯一 `id`**：DSH 会校验 message 事件形状（`id`/`role`/`source.kind`/`content`），缺 `id` 直接整份会话拒开（`SessionPersistenceCorruptionError ... lacks an identified message`）。老插件注入的 `{type:'user',source,content}` 就是事故源；现在 `withIdentity()` 统一补 `role:'user'`、`id:randomUUID()`、删 `type`——**别再绕过它**。
2. **空文本气泡不渲染图**：`bubble.say({text:'',image})` 会被 `src/host/broadcast.ts:136` 拒；就算放行，空文本盒子塌陷、绝对定位的图跟着消失。表情包正确姿势：`say` 写 `{ text: clipped, image, phase: 'image' }`（**不带 duration**），`src/shared/state.ts` 的 `SayCue` 保留 `phase`，`src/client/pet.ts` 用 `triggerWhisper(..., say.phase)`，`phase==='image'` 直接 `setWhisperPhase('image')`；`MEME_TAIL_DELAY_MS=1000` 是「念完 1 秒再出图」。
3. **摘要别二次截断**：`toPet` 在 `opts.summary` 时不要走 `plainText` 的截断，否则句子被切半。
4. **TTS 协议**：`edge` 偶发 0 字节（空音频）→ 已加一次重试；`system` 走 Windows SAPI 最稳。写配置时别把 `model.tts.protocol` 顺手写回 `edge`。
5. **CRLF**：`src/host/index.ts`、`src/host/pet-menu.ts` 是 CRLF。用脚本打补丁先把 `\r\n` 归一成 `\n`，改完再转回去，否则 diff 全乱/补丁匹配失败。
6. **electron-builder 在 Electron-as-node 下跑**：CLI 用 `Unknown argument` 报错、API 报 `Invalid package …app.asar`；`build-nsis.cjs` 首行必须 `process.noAsar = true`。
7. **杀进程**：脚本里 `taskkill /F /IM BodyOfFish.exe` 可以，但**绝不能 `taskkill /T` 杀 DSH**——用 `ELECTRON_RUN_AS_NODE` 起的 node 映像名也叫 `DeepSeek Harness.exe`，会把自己一起带走；自检要排除 `process.pid`/`process.ppid`。
8. **中文与 shell**：git-bash 的 `curl -d 中文` 会被 GBK 吃，JSON 请求走 node 脚本；git-bash 的 `python` 是 Store 空壳（静默不执行还返回 0），要用 `C:\Users\hb109\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe`。
9. **删 junction**：`Remove-Item -Force` 会顺着链接删目标（危险），删链接用 `[System.IO.Directory]::Delete($p,$false)`；ps1 带中文必须存 UTF-8 with BOM。
10. **刷新 vs 重启**：DSH 里插件改动点右上角「刷新」能原地生效；**壳/宿主/安装包改动必须重启**。身体换 `lib/*.js` 后要重启身体进程。
11. **装在带 `Low` 完整性标签的盘上会「只有管理员能开」**：Windows 按「从哪个文件启动」给进程定完整性——从 `Low` 标记的 exe 启动的进程也跑在 Low，不能写 Medium 的对象，身体的 `%TEMP%\dsh-pet-logs\launcher.log` 追加被拒 → 启动链在渲染器前断掉，双击没反应、exit=0。查：`icacls "盘符:\"` 看 `Mandatory Label\Low Mandatory Level`；改：`icacls "盘符:\" /setintegritylevel Medium /T /C /Q`（先 `icacls "盘符:\" > 备份.txt`）。**不是代码问题，别去改 exe/清单**（11-02 `D:\AI` 踩过）。
